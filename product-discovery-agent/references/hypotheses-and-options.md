# Hypothesise and explore

Start each stage by reading the discovery record and showing the mandatory memory and reflection checkpoint. At exit update changed interpretations, gate, and next action.

## 5. Hypothesise

Translate supported insights into falsifiable beliefs. For a causal problem hypothesis use: "For [segment/context], [mechanism] contributes to [observed consequence], which would be weakened by [disconfirming observation]." For a solution hypothesis use: "If [response], [observable behaviour/outcome] should change relative to [baseline/comparison] within [period], because [mechanism]." Do not infer the latter directly from the former.

List relevant assumptions across desirability, usability, feasibility, viability, adoption, trust, access, operations, regulation, security, data rights, and economics. Prioritize by consequence if false and uncertainty, without fake numeric precision. Link each consequential assumption to existing evidence and a credible test.

**Gate:** The causal belief and critical assumptions can be disproved by an observable result.

## 6. Explore

Generate materially distinct responses to a supported opportunity: current experience, operations, policy, communication, assisted service, partner approach, new capability, or no intervention as context warrants. Explain each mechanism and what must be true for it to work. Compare customer and business value, effort, feasibility, trust, access, dependencies, reversibility, and unintended effects.

Select a leading direction only provisionally. State the evidence for it, strongest alternative, and what would overturn its ranking. Weak evidence calls for a small exploratory test rather than a confident roadmap recommendation.

**Gate:** Distinct approaches and trade-offs are visible, with consequential unknowns identified for validation.
